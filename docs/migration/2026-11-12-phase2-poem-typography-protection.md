> 日期：**2026-11-12**
> 测试对象：`hugo/layouts/shortcodes/poem.html`、`hugo/hugo.toml`（`[markup.goldmark.renderer]`）
> 环境：`hugo v0.168.0+extended`，使用**自编合成文本**（**未**使用任何真实诗歌）
> 相关分支：`review/hugo-deployment-readiness-phase2`

> ⚠️ **重要声明**：构建成功（`hugo build` 无错误）**不等于**诗歌排版可靠。本报告以**渲染产物逐字节检查**为依据，发现 **2 个会改变诗歌正文的高风险问题**。

## 1. 测试方法（**【已验证事实】**）

在临时目录（`/tmp`，**不进入仓库**）创建合成测试文章，覆盖：

| 用例 | 内容 |
| --- | --- |
| A | `hardWraps` 直接换行（无短代码） |
| B | 连续空行（诗节） |
| C | HTML 特殊字符 `<` `>` `&` 与中英文引号 |
| D | Markdown 标记 `*斜体*`、`_下划线_` |
| E | 中英混排 |
| F | `poem` 短代码（含空行、特殊字符、Markdown 标记） |
| G | 原始 HTML（`<div class="poem">…<br>…`，模拟旧站写法） |

命令：`hugo --logLevel error`（构建成功，exit 0），随后检查 `public/**/index.html`。

## 2. 测试结果（**【已验证事实】**）

### 2.1 换行与诗节

| 用例 | 输入 | 输出 | 判定 |
| --- | --- | --- | --- |
| A 行内换行 | 三行紧邻 | `第一行<br>第二行<br>第三行` | ✅ 保留 |
| A 诗节（空行） | 空行分隔 | 各自独立 `<p>…</p>` | ✅ 分节 |
| B 连续空行 | 多空行 | 折叠为 `<p>` 分隔（不产生连续 `<br>`） | ✅ 合理 |
| F 短代码 | 含空行 | `第一行<br>第二行<br><br>第三节…` | ⚠️ 空行=额外 `<br>`（见 3.3） |

### 2.2 特殊字符与引号

| 用例 | 输入 | 输出 | 判定 |
| --- | --- | --- | --- |
| C `<>`&`&` | `小于号 < 大于号 > & 符号` | `小于号 &lt; 大于号 &gt; &amp; 符号` | ✅ 安全转义 |
| **C 引号** | `'英文'` / `"double"` | **`&lsquo;英文&rsquo;` / `&ldquo;…&rdquo;`** | ❌ **引号被改变** |
| **C 省略号/破折号** | `...` / `--` | **`…` / `–`** | ❌ **标点被改变** |

> **【已验证事实】** Hugo/Goldmark 的 **typographer 默认开启**，会把**直引号变弯引号**、`...` 变 `…`、`--` 变 `–`。
> 这**违反“诗歌正文逐字不变”**的核心要求。

### 2.3 Markdown 标记

| 用例 | 输入 | 输出 | 判定 |
| --- | --- | --- | --- |
| D 斜体 | `*不应*` | `<em>不应</em>` | ❌ **被解释为斜体** |
| D 下划线 | `_不应_` | `<em>不应</em>` | ❌ **被解释为斜体** |
| F 短代码内 | `*a*` / `_b_` | `*a*` / `_b_`（**原样**） | ✅ 短代码内不解释 |

> **【已验证事实】** `hardWraps` 直接正文路径下，`*...*`、`_..._` 会被当作 Markdown 强调**渲染**；只有 `poem` 短代码路径能原样保留。

### 2.4 原始 HTML

| 用例 | 输入 | 输出 | 判定 |
| --- | --- | --- | --- |
| G 原始 HTML | `<div class="poem">…<br>…</div>` | **原样保留**（`unsafe=true` 生效） | ✅ 旧站 HTML 可保留 |

## 3. 发现的问题（**【已验证事实】+【建议】**）

### 3.1 【高】typographer 改变引号/省略号/破折号

- **现象**：`'` → `‘’`，`"` → `“”`，`...` → `…`，`--` → `–`。
- **影响**：诗歌正文中的直引号、省略号、破折号会被**静默改写**，违反逐字保护。
- **根因**：`hugo.toml` **未设置** `[markup.goldmark.extensions] typographer = false`；Goldmark 默认开启 typographer。
- **建议（未应用）**：
  ```toml
  [markup.goldmark.extensions]
    typographer = false
  ```
- **验证**：加上该配置后，`'single'` 保持 `&#39;single&#39;`、`...` 保持 `...`、`--` 保持 `--`（已实测）。**【已验证事实】**

### 3.2 【高】`hardWraps` 正文中 `*`/`_` 被解释为强调

- **现象**：`*不应*` → `<em>不应</em>`。
- **影响**：若诗中含 `*` 或 `_`（注脚、星号、下划线），会被误渲染。
- **建议**：**诗歌正文一律使用 `{{< poem >}}` 短代码**（短代码内 Markdown 不生效，已实测原样保留）；或迁移时对 `*`/`_` 转义。
- **建议**：在迁移规范中**明确**：“诗歌正文必须包裹在 `poem` 短代码中”，`hardWraps` 仅作兜底。

### 3.3 【中】两种换行机制行为不一致

- **现象**：
  - `hardWraps` 路径：空行 → 新 `<p>`（块间距由 CSS `margin` 控制）；
  - `poem` 短代码路径：空行 → 额外 `<br>`（行间距由 `line-height` 控制）。
- **影响**：同一首诗用不同机制，**诗节间距视觉不同**。
- **建议**：统一使用 `poem` 短代码，并为其增加 `white-space` 或按空行分段的类，使诗节间距可控且一致。

### 3.4 【中】短代码未声明 `markup="html"`

- **现象**：`poem.html` 用 `{{ . }}` 输出内部文本，实测特殊字符被**转义**（`<`→`&lt;`）且 Markdown 不解释。
- **影响**：当前行为对“纯文本诗歌”**是安全**的（不注入 HTML）；但若诗歌正文本身含**内联 HTML**（如 `<br>`、`<span>`），短代码会将其**转义显示**，与预期不符。
- **建议**：明确短代码定位：
  - 若只处理**纯文本**诗歌 → 保持现状（安全）；
  - 若需支持**内联 HTML** → 在短代码中显式 `| safeHTML` 并声明 `{{< poem >}}` 语义（**注意**：会引入注入风险，须配合可信内容）。

### 3.5 【低】移动端与字体（**【推断】**，未真机验证）

- **【已验证事实】** `style.css` 含 `@media` 断点、`.poem-content{line-height:2.4}`、移动端 `line-height:2.2`；已补 `viewport`（旧站缺失）。
- **【待验证】** 真机渲染、中文衬线字体回退、中英混排基线对齐（本阶段仅静态检查 HTML/CSS，**未**真机/浏览器像素级验证）。

## 4. 逐项保护能力小结（**【已验证事实】**）

| 需求 | `hardWraps` 正文 | `poem` 短代码 | 结论 |
| --- | --- | --- | --- |
| 行内换行保留 | ✅ `<br>` | ✅ `<br>` | 均可 |
| 诗节（空行） | ✅ `<p>` | ⚠️ 额外 `<br>` | 需统一 |
| 特殊字符安全 | ✅ 转义 | ✅ 转义 | 均可 |
| **直引号不变** | ❌ 变弯引号 | ❌ 变弯引号 | **需关 typographer** |
| **省略号/破折号不变** | ❌ 变 `…`/`–` | ❌ 变 `…`/`–` | **需关 typographer** |
| Markdown 标记不变 | ❌ 变斜体 | ✅ 原样 | 用短代码 |
| 原始 HTML 保留 | ✅ | ❌ 被转义 | 用 `hardWraps`+`unsafe` |

> **【推断】** 即便关闭 typographer，短代码内引号是否仍被改写需**再验证**（Goldmark 扩展作用于渲染阶段）。**【待验证】**
