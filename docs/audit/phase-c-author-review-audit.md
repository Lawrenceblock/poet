## 1. 记录标识的稳定性与唯一性（**已验证**）

**检查方法**
```bash
git show review/author-review-materials:docs/poetry-discovery/poetry-candidates.v2.csv > /tmp/cand_v2.csv
git show review/author-review-materials:docs/author-review/poetry-candidates-author-review.csv > /tmp/author_review.csv
python3 - <<'PY'
import csv,re
cand=list(csv.DictReader(open("/tmp/cand_v2.csv",encoding="utf-8")))
ids=[r["candidate_id"] for r in cand]
print("count",len(ids),"unique",len(set(ids)))
print("all C####",all(re.match(r"^C\d{4}$",i) for i in ids))
nums=sorted(int(i[1:]) for i in ids)
print("contiguous",nums==list(range(nums[0],nums[-1]+1)),nums[0],nums[-1])
PY
```

**实际结果**
- `candidate_id` 共 137 个，全部形如 `C####`，**唯一且连续**（C0001–C0137）。
- `source_post_id` 在候选集中**唯一**（137 个不同值）。
- 作者审阅表 `candidate_id` 与 v2 **完全一致**：`set(v2) - set(review) = ∅`，`set(review) - set(v2) = ∅`。

**结论**：标识稳定、唯一、可跨文件引用。✅

## 2. CSV 与 v2 数据一致性（**已验证 / 存在风险**）

**实际结果**
- 行数：v2 候选 **137**，作者审阅表 **137**，逐一对应，**无遗漏、无重复**。
- 候选 `source_url` 全部命中库存表（`candidates not in inventory: []`）。

**存在风险：字段丢失（信息裁剪）**

审阅表只带 20 列，v2 的部分字段**未透传**：

| v2 字段 | 是否进入审阅表 | 影响 |
| --- | --- | --- |
| `authorship_evidence` | ✅（“分类依据（脚本）”） | — |
| `confidence` | ✅（“置信度（脚本）”） | — |
| `note`（截断摘录） | ✅（“备注（脚本，截断摘录）”） | — |
| `labels` | ❌ | 作者看不到原文标签（如 `诗歌/新疆`） |
| `auto_basis` | ❌ | 作者看不到自动判定的完整理由串 |
| `title_source` / `has_own_title` | ❌ | 作者看不到“标题来自文章名/内文署名/无标题” |
| `full_text_present` | ❌ | 作者无法确认是否抓取到全文 |
| `source_post_title` | ⚠️ 以“文章标题”呈现 | 未区分“文章标题”与“作品标题” |

**影响**：作者在缺少 `labels` 与 `title_source` 的情况下，难以判断“作品是否有独立标题”，
而这一点直接决定**新站 URL 与显示标题**。建议补齐（见第 5 节）。

## 3. 分类规则清晰度（**部分验证 / 存在风险**）

**规则来源**：`tools/poetry-discovery/build_inventory_v2.py`（`classify_v2`）。
规则本身**定义清晰**：

| 类别 | 规则 | 置信度 |
| --- | --- | --- |
| A | **必须**有结构化署名（`文/安然`、`安然/文`、`◎安然`、`by An Ran`） | 0.85–0.90 |
| B | 有诗歌信号（标签/标题/诗行）但**无结构化署名** | 0.40–0.60 |
| C | 安然为**译者**（`安然译`、`译者：安然` 等） | 0.70 |
| D | 标题含评论/创作谈/消息关键词 | 0.60 |
| E | 引用/转载他人作品且无安然署名 | 0.50 |

**风险：作者可见的“分类含义”列覆盖不全**

`tools/author-review/build_author_review.py` 的 `CATEGORY_LABEL` 定义了 A–E 五类含义，
但生成时使用 `CATEGORY_LABEL.get(row["category"], "")`。

**实际结果**：v2 候选实际只出现 A/B/C/D 四类（E 类为 0 条）。
经核对，`CATEGORY_LABEL` 含 A–E 五个键，故 A–D 行均有含义文本，**未出现空值**；
但作者审阅表**没有 E 类行**，而 `batch-CD.md` 的标题却写作“C/D/E 类候选”——
**标题与内容不一致**（文档瑕疵，非数据错误）。

**风险：v1/v2 分类差异对作者不可见**

`classification-diff-v1-v2.csv` 记录了 v1→v2 的改动（A 类在 v2 因“无署名”被降级为 B），
但**审阅表未提示“此条曾被判为 A、现降为 B”**，作者无法看出分类的**历史变动**。

**风险：文章 ≠ 作品**

v2 已明确 `work_count_estimate` 描述的是**作品数而非文章数**，7 条标记 `>=2`、130 条 `unknown`。
但审阅表的列名“当前作品数量估计”对普通读者仍可能被误读为“篇数=首数”。
审阅指南需再次强调（已部分强调，见 `README.md`）。

## 4. 作者可操作性（**部分验证**）

**现状**：审阅表提供
`需要作者确认的问题`、`作品边界问题`、`作者确认状态`（初始 `待作者审阅`）。

**不足**：
1. 无**勾选式**字段（如 `确认=是/否/存疑`）与**自由文本**列（作者无法写备注）。
2. 无**分类修改**列（作者无法直接改 A/B/C/D 的建议值）。
3. 无**作品标题**列（作者无法登记“这首诗的真实标题”）。
4. CSV 对非技术作者不友好；`batch-*.md` 更友好，但**没有回填机制**（作者在 md 上批注后无法结构化回收）。

**结论**：可读，但**不可结构化回填**。

## 5. 审阅结果回写安全性（**存在风险**）

**检查方法**
```bash
sed -n '/def main/,$p' tools/author-review/build_author_review.py   # 观察写入行为
```

**实际结果**：`main()` 每次都：
```python
write_csv(out_rows)     # 直接覆盖 docs/author-review/poetry-candidates-author-review.csv
```

**风险**：作者一旦在该 CSV 中填写 `作者确认状态`，**再次运行脚本会整表覆盖**，
作者的人工确认**无备份、无提示、不可恢复**。

**建议（本阶段不实施）**：
- 生成脚本**永不写回**作者已填写的文件；
- 作者确认结果**单独存于** `docs/author-review/review-responses.csv`（只含 `candidate_id` + 作者字段）；
- 由合并脚本以 `candidate_id` 为主键**只读合并**，生成带确认状态的**新**视图文件；
- 引入**导出/导入**分离：生成视图（只读）↔ 收集回复（可写）。

## 6. 审阅历史与时间戳（**存在风险**）

**实际结果**：审阅表与 v2 均**无** `reviewed_at`、`reviewed_by`、`revision`、`supersedes` 等字段。
Git 提交历史可记录**文件级**变化，但**无法记录逐条确认时间**。

**建议**：回复文件增加 `确认时间`、`确认人`、`记录版本` 三列，并保留每次回复的 Git 提交。

---

## 7. 审阅状态与发表状态分离（**存在风险**）

**实际结果**：目前只有一个 `作者确认状态` 列，**同时承担**“是否为作品/归属/是否可公开”多种含义。

**建议**：拆分为**三个正交字段**（本阶段仅建议）：

| 字段 | 取值示例 | 含义 |
| --- | --- | --- |
| `归属确认` | 安然原创 / 他人作品 / 译作 / 存疑 | 作品**归属** |
| `作品边界` | 单首 / 多首 / 非诗 / 待定 | 作品**边界** |
| `发表授权` | 未授权 / 授权公开 / 暂缓 / 撤下 | 是否可**公开** |

三者相互独立：一条可“确认为安然原创、单首、但暂缓公开”。
