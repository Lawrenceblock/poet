## 1. 复核起因

任务指出：`ORIGINAL_AUTHOR_RE` 含 `An Ran`，过于宽泛——正文只要出现 `An Ran` 即可能被当作安然原创署名。本报告核实该风险，并提出更严格规则。

## 2. 原始规则（v1，**【已验证事实】**）

`ORIGINAL_AUTHOR_RE` 由以下子模式用 `|` 组成（`re.I`）：

| 子模式 | 含义 |
| --- | --- |
| `文\s*[/|｜]\s*安然` / `文/安然` | 中文署名“文/安然” |
| `安然\s*[/|｜]\s*文` | 中文署名“安然/文” |
| `作者\s*[:：]\s*安然` | 中文署名“作者：安然” |
| `[/|｜]\s*安然\s*$` | 行尾“/安然” |
| `by\s+an\s+ran` | 英文署名“by An Ran” |
| `An\s+Ran` | **裸名**（无边界、无上下文） |

只要 `ORIGINAL_AUTHOR_RE` 命中（正文**或标题**），即判 **A 类**。

## 4. `An Ran` / `by An Ran` 的误判风险（**【已验证事实】**）

### 4.1 裸名无词边界（substring 风险）

`An\s+Ran` **未加词边界**，会匹配更长的英文单词内部。合成字符串实测：

| 输入 | 裸名 `An\s+Ran` | 加边界版本 |
| --- | --- | --- |
| `Japan Range is vast` | **命中** `an Ran` | 不命中 |
| `The Urban Range` | **命中** | 不命中 |
| `American Randomness` | **命中** | 不命中 |
| `Kazakhstan Range` | **命中** | 不命中 |

- **实际影响**：在 305 篇中**未造成实际误判**——唯一多出的松散匹配是 `2025-05-08` 的 `An Ran’s`（真实指代安然）。**【已验证事实】**
- 但这是**潜在缺陷**：一旦出现 `Japan Range` 等词即可能误判。**【建议】** 加词边界 `(?<![A-Za-z])An\s+Ran(?![A-Za-z])`。

### 4.2 “by An Ran” 的其它风险

- **译者误读**：若出现 `translated by An Ran`，说明安然是**译者**，不是作者。全库实测 **0 条** 该结构。**【已验证事实】**
- **他人引用**：若正文引用他人文章并提及安然，可能误判。全库仅 `2019-01-12` 一处裸提“pen name is An Ran”，该文**无诗歌信号**，未被判 A。**【已验证事实】**
- 结论：`by An Ran` 本身是**较可靠的署名结构**，风险主要来自**无边界**与**译者上下文**。

## 7. 更严格的原创署名识别规则（**【建议】**）

### 7.1 应**优先匹配**的明确署名结构

```
# 中文署名（结构性，非裸名）
(?:文|作者)[ \t]*[/|｜:：][ \t]*安然
| 安然[ \t]*[/|｜][ \t]*文
| ◎[ \t]*安然
| [/|｜][ \t]*安然[ \t]*(?=$|\n)          # 行尾“/安然”

# 英文署名（加词边界）
(?<![A-Za-z])by[ \t]+An[ \t]+Ran(?![A-Za-z])
```

> 注意：**不应**强制“行首锚定”。实测中 Blogger 的 `##CONTINUE##` 会与署名粘连（`##CONTINUE##安然/文`），行首锚定会**漏判**该署名。

### 7.2 应**单独归入翻译类（C）**的规则（在作者署名判定**之前**执行）

```
(?:translat\w*|trans\.)[ \t]*:?[ \t]*by[ \t]+An[ \t]+Ran
| 安然[ \t]*[译譯]
| [译譯][ \t]*[:：]?[ \t]*安然
| (?:译者|譯者|翻译|翻譯)[ \t]*[:：]?[ \t]*安然
```

> 冒号应**可选**：实测 `翻译 安然`（无冒号）是真实写法。

### 7.3 不得把正文中普通出现的名字当作署名

- **移除**裸名 `An Ran` 作为独立判据；
- 裸名仅可用于**标记“提及”**，**不得**单独触发 A 类；
- 英文署名**必须**带 `by` 前缀且带词边界。
